## 修复：相对 .md 链接点击后仍为空白（路径百分号编码导致 set_file 找不到文件）
- 现象：GUI 中点击指向其他 .md 的相对链接（尤其含中文/空格文件名，如 `09-Kotlin 重构决策与风险.md`），不渲染目标文件、显示空白。
- 根因：`frontend/src/App.vue` 的 `resolveAndOpen` 用 `new URL(href, base).pathname` 解析相对链接。WHATWG URL 会把中文等非 ASCII 字符百分号编码（`我的笔记`→`%E6%88%91...`、中文文件名→`%XX`），而 `%20` 又被解码成空格，得到「半编码」混合路径，与磁盘真实路径不符。Rust `set_file` 用 `PathBuf::from` 直接拼、不解码百分号 → 判定文件不存在 → 导航失败（空白）。
- 修复：改为 `decodeURIComponent(new URL(href, base).pathname)`，把 pathname 还原成真实文件路径；`resolveAndOpen` 改为 async，当 `currentPath` 为空时回退调用 `get_file_path`（Rust 端权威路径）；目录截取正则改为分隔符无关 `[\\/][^\\/]*$`。最终仍调 `openMdFile` 以 HTML 重新渲染目标 .md。
- 验证：Node 模拟——修正前 target 为 `%E6%88%91...` 半编码路径；修正后正确还原为 `/Users/edy/docs/我的笔记/09-Kotlin 重构决策与风险.md` 等（`./`、`../` 也正确）。`pnpm build` 通过，产物含 `decodeURIComponent`。
- 注：Windows 路径（`C:\...`）下 `file://` base 拼接仍不理想，用户当前为 macOS，未深究。

## 新功能：工具栏前进/后退导航（历史栈）
- 需求：链接跳入某文件后容易迷失，需浏览器式前进/后退。用户确认选「方案 A 前进/后退历史栈」（而非文件浏览器侧边栏）。
- 实现：
  - `frontend/src/App.vue`：新增 `history`(路径数组) + `historyIndex`；`pushHistory(path)`（与当前相同不重复压栈；处于历史中间则截断前进分支）；`openFileAndRender(path)`（实际渲染，前进后退也走它）；`openMdFile(path)`（pushHistory + render，链接点击/打开文件/拖拽入口）；`goBack()`/`goForward()`（移动 index 并 render）；`canGoBack`/`canGoForward` 两个 computed。
  - `onOpenFile` 改为调用 `openMdFile`（统一入栈）；`onMounted` 以初始文件 seed 历史栈。
  - 键盘快捷键：`Alt+←` 后退、`Alt+→` 前进（保留 `Cmd/Ctrl+O` 打开）。
  - `Toolbar.vue`：新增 `canGoBack`/`canGoForward` props 与 `nav-back`/`nav-forward` emits；左侧文件名后加两个图标按钮（`.btn-icon` 样式，禁用态跟随 computed）。
  - `i18n/index.js`：新增 `navBack`/`navForward`（zh/en）。
- 验证：`pnpm build` 通过；产物含 `nav-back`/`nav-forward`/`canGoForward`/`navBack`/`navForward`。

## 已实现：Mermaid / flowchart 解析为内嵌 SVG
- 决策（用户拍板）：① 渲染取回用 `--dump-dom --virtual-time-budget`（零新增依赖）；② mermaid.min.js vendored 内置（templates/assets/mermaid.min.js，mermaid@11 UMD，`globalThis.mermaid`）；③ DOCX **直接内嵌 SVG 矢量图**（现代 Word 支持，不走 PNG）；④ 完整识别含别名围栏。
- 代码落点：`crates/md2x-core/src/mermaid.rs`（新模块）。
  - `render_mermaid_blocks(html)`：HTML 路径，替换 `<pre><code class="language-XXX">` 为 `<div class="mermaid-diagram">SVG</div>`。
  - `is_mermaid_source(lang, source)`：别名围栏（mermaid/flowchart/flow/sequenceDiagram/classDiagram/...）+ 无语言时首行关键字嗅探。
  - `reconstruct_source(lang, body)`：**关键坑**——comrak 把 ```` ```sequenceDiagram ```` 的 `sequenceDiagram` 当"语言"塞进 class，代码体丢失首行关键字，喂给 mermaid 会渲染失败。需把语言补回首行（仅当代码体首行还不是关键字时）。
  - `render_mermaid_svg_from(lang, literal)`：DOCX AST 路径专用，先 reconstruct 再渲染 SVG 字符串。
  - 降级：无 Chrome/渲染失败 → 保留原代码块，不中断。
- 接线：`converter::convert_markdown_to_html_with_mermaid` 统一入口，CLI 与 GUI（get_html/preview_pdf/render_full_html）全部走它，保证"只解析一次"；DOCX 在 `docx/render.rs` 的 CodeBlock 分支调用 `render_mermaid_svg_from` 内嵌 SVG（依赖 `image` 模块已有的 svg 尺寸解析 + `[Content_Types].xml` 自动声明 image/svg+xml）。
- 附带修：`chrome.rs` 的 `generate_pdf`/`generate_png` 缺 `--no-sandbox --disable-gpu --disable-dev-shm-usage`，本机沙箱下 PDF/PNG 生成失败（预存问题，与 mermaid 无关），已补上，mermaid SVG 经 HTML 流入 PDF/PNG 正常。
- 验证：CLI 对含 mermaid/sequenceDiagram/裸 graph/普通 rust 的 md，`--format html` 出 3 个内嵌 SVG、无残留代码块；`--format docx` 内嵌 3 个 `word/media/imageN.svg` 且 Content_Types 声明 svg+xml；`--format pdf/png` 正常生成。6 个 unit test 通过（is_mermaid_source/reconstruct/unescape）。整个 workspace（含 GUI）编译通过。
