## 全宽功能：编译警告清零 + 最终干净实现

- 用户指出编译时有一堆警告没正视。核查为 11 条 `non_snake_case`：是我之前为"绕开 Tauri 大小写"把 `full_width` 全改成 `fullWidth` 留下的歪招（camelCase 命名不符合 Rust 规范）。
- 干净修法（已落地）：Rust 全部保持 snake_case（`full_width`）+ 给前端会调用的命令 `preview_pdf`/`export_html`/`export_pdf` 加 `#[tauri::command(rename_all = "camelCase")]`，让 JS 的 `fullWidth` 自动映射到 Rust 的 `full_width`。`get_html` 不再接收该参数（前端自己注入 CSS），直接渲染标准宽度。
- 结果：`cargo build -p md2x-gui` → **0 警告 0 错误**（之前 11 条 non_snake_case 全清）。

## 全宽功能最终实现形态（纯前端注入，最稳）

- 后端 `get_html` 不再管全宽（始终渲染标准宽度）；`preview_pdf`/`export_html`/`export_pdf` 仍接收 `full_width: Option<bool>`（经 rename_all 接收前端 camelCase），用于 PDF/导出宽度。
- 前端 `App.vue`：点全宽按钮 → `toggleFullWidth` → `setFullWidth` → `loadPreview` → `get_html`（无参）→ `applyFullWidth(html)` 在 `<head>` 注入全宽 `<style>`（隐藏侧栏 / `.layout` none / `.main-content` 归零 / `.markdown-body` 100%）→ iframe 重渲染。
- 这彻底绕开 Tauri 命令参数传递（大小写 / reject）这条易碎链路，按钮点击=纯前端状态变化，几乎不可能"没反应"。
- 已用 Chrome 无头实测：标准 HTML + 该段前端 CSS 注入后，1600 视口下正文 1552px（仅 24px 边距）、侧栏隐藏、满宽。CSS 正确性已钉死。

## 关键经验（Tauri v2 命令参数）

- Tauri v2 `#[tauri::command]` 参数**默认 `rename_all = "keep"`**，不会自动把 JS camelCase 转 Rust snake_case。JS 传 `fullWidth`、Rust 收 `full_width` → serde reject → `invoke` 抛错被前端 catch 吞掉 → 页面"完全没反应"。
- 正解二选一：① Rust 保持 snake_case + 命令加 `rename_all = "camelCase"`（前端 camelCase 不变，推荐）；② 前端直接发 snake_case key。
- 编译警告不能无视：camelCase 改法的 11 条 `non_snake_case` 虽不致命，但是"歪招"的信号；应回归规范命名 + 用框架机制（rename_all）解决，而非改命名风格。

## 全宽按钮"点了没反应"的真正根因（双击取反 bug，2026-08-13 下午）

- 之前一直以为是 Tauri 参数大小写 / 旧进程 / 前端未重建。本轮核查 `frontend/dist` 已含 `md2x-fullwidth` 注入代码（hash `index-BycXFBEG.js`），证明前端包是最新的——**不是构建陈旧**。
- 真因：`Toolbar.vue` 的 `onToggleFullWidth` 先 `settings.setFullWidth(!fullWidth)` 再 `emit('toggle-full-width')`，而 `App.vue` 的 `toggleFullWidth` 又 `settings.setFullWidth(!fullWidth)` 一次。**一次点击取反两次 → 净不变**，按钮高亮与页面宽度都"等于没点"。完美解释"点击与没点击一样"。
- 修法：`Toolbar.vue` 的 `onToggleFullWidth` 只 `emit('toggle-full-width')`，真正的取反 + 重渲染由 `App.vue` 统一负责（单一真相源）。改后 `setFullWidth` 全仓仅 `App.vue` 调用一次。
- 教训：按钮"无任何变化"这类症状，优先排查**事件是否在同一状态上被多次取反/重复处理**，而不是先怀疑构建或参数传递。双绑/双处理事件流是隐蔽高发点。
- ✅ 用户已验证生效：退出旧窗口、用新二进制重开后，全宽按钮正常切换（高亮 + 页面满宽）。

## 调试方法论（已验证有效）

- 用 Chrome `--headless --dump-dom` + 注入测量脚本读 `getBoundingClientRect`，可无头实测 CSS 真实渲染宽度，绕开 GUI 歧义，给确定性结论。
- 改 Rust 后端后必须杀旧 `md2x-gui` 进程（`pgrep -f target/debug/md2x-gui` → `kill`）再启动，否则旧窗口用旧二进制。
